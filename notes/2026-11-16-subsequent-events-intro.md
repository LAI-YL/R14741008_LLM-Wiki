# 期後事項：哪些要調整、哪些只要揭露

## 研究問題

什麼是期後事項（Subsequent Events）？哪些要調整財報、哪些只要揭露？雙重日期又是什麼？

## 摘要

期後事項是資產負債表日之後、查核報告日之前發生的事項，屬於查核流程中「完成查核」階段要評估的項目。判斷的關鍵是「**狀況**在期末是否已經存在」：期末已存在、期後才取得證據的是 Type 1（調整事項），要**調整財報數字**；期末後才發生的新狀況是 Type 2（非調整事項），**不改數字**，重大者在附註揭露。若查核報告日之後才發生需要揭露的事項，可以用**雙重日期**，只把查核人員的責任延長到該附註事項。

## 本文

### 1. 期後事項是什麼

期後事項是指**資產負債表日之後、查核報告日之前**發生的事項。在查核流程中，它屬於第 5 步「完成查核」，和繼續經營評估一起進行。非上市公司的對應準則是 AU-C 560（期後事項與期後始獲知之事實）。（[[subsequent-events]]、[[overview]]）

### 2. Type 1：調整事項

期末**已經存在**的狀況，期後才取得證據 → **調整財報數字**。例如：期末前已陷入財務困難的客戶在期後破產；期末前的訴訟在期後判決確定。（[[subsequent-events]]）

### 3. Type 2：非調整（揭露）事項

期末後**才發生**的新狀況 → **不改數字**，重大者在附註揭露。例如：期後廠房火災、發行新股、重大併購。重大的 Type 2 事項也常是強調事項段的題材。（[[subsequent-events]]、[[emphasis-of-matter]]）

### 4. 判斷關鍵

| 問題 | Type 1 調整事項 | Type 2 非調整事項 |
|---|---|---|
| 狀況在期末是否已存在 | 已存在 | 期末後才發生 |
| 財報怎麼處理 | 調整數字 | 不改數字，重大者揭露 |
| 例子 | 客戶期後破產（期末已有困難） | 期後廠房火災 |

判斷關鍵是「**狀況**在期末是否已存在」，不是「**消息**何時知道」。（[[subsequent-events]]）

### 5. 雙重日期（Dual Dating）

例如報告日期寫成「February 15, 2026, except as to Note 7, which is as of March 3, 2026」。雙重日期只把查核人員的責任延長到**該附註事項**，不會延長整份財報的責任。（[[subsequent-events]]）

> [!exam] 考點
> 雙重日期只延長**單一附註**的責任；判斷 Type 1／Type 2 看的是**狀況**何時存在，不是消息何時知道。（[[subsequent-events]]）

## 知識庫目前的缺口

- 上市公司（PCAOB）對應的期後事項準則：知識庫尚未確認編號（已列入待查證），需要以官方資料（R009、R010）確認後更新 wiki。
- 查核人員在期後期間具體要執行哪些程序（例如詢問、閱讀會議紀錄等）。
- 查核報告日之後、財報發布前，或財報發布後才發現事實時，查核人員的責任。
