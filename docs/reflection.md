# 反思：哪裡最常出錯？檢查要放在哪裡？

依據：[執行紀錄：審計是什麼？](runs/2026-11-16-what-is-audit.md)，以及建立知識庫時的修正紀錄（`wiki/log.md`）。

## 1. 哪個節點最常出錯？

| 節點 | 錯誤 | 次數 | lint 抓得到嗎 |
|---|---|---|---|
| 2 Ingest | 可疑說法寫進 wiki、金額 `$`、表格分隔符號 | 3 | 修改規則後可以 |
| 5 逐頁稿 | 簡體字「来源」×2、筆記沒有的評價句、流程衝突（播放器） | 4 | 簡體字、播放器可以；**多加的句子不行** |
| 7 HTML 簡報 | 章節頁白字白底、封面斷行、圖解字太小 | 3 | **都不行** |

最常出錯的是**節點 5（逐頁稿）**，但最危險的是**節點 7（HTML 簡報）**：它的錯誤 lint 全部抓不到，只能靠截圖，而且一旦發生就會影響所有簡報。

兩類錯誤的根本原因不同：

- **內容錯誤**（多寫一句、可疑說法）：AI 在「改寫、濃縮」時很自然地加上自己的評價。下游只能用上游的內容，這條規則必須靠逐句比對才守得住。
- **畫面錯誤**：規則和 lint 只看 Markdown 文字，看不到渲染後的樣子。

## 2. 檢查往前移到哪一步？

| 原本在哪裡發現 | 往前移到 | 做法 |
|---|---|---|
| 簡報播放時才看到 `[!todo]`、可疑內容 | 節點 2 Ingest | 規則：不確定內容只寫在 source 頁；lint 擋下其他頁的 `[!todo]` |
| 簡報上沒有學習目標、小測驗 | 節點 5 逐頁稿 | 規則＋lint 檢查教學結構（本次新增） |
| 封面副標題每份都一樣 | 節點 5 逐頁稿 | lint 擋下通用句與重複副標題 |
| 圖片沒登記、用了草稿吉祥物 | 節點 5 逐頁稿 | lint 檢查 `assets/index.md` 登記表 |
| 章節頁看不見（所有簡報共用的樣式問題） | **選主題時** | 選定或修改主題時，**每一種頁型都要截圖預覽**，不能只看幾種 |

## 3. 是否修改 workflow？

有，本次一共改了三處：

1. **新增「教學結構」**（AGENTS.md 6.6 第 6 點）：先想一想 → 學習目標 → 章節 → 小測驗＋解答 → 總結，lint 同步檢查。
2. **解開流程衝突**：原本 lint 要求播放器已存在，但規則要求逐頁稿先停下來給使用者確認。改成「尚未產生播放器」只是提醒，不算錯誤。
3. **新增 `docs/` 與 6.9 流程紀錄**：每次執行都留下紀錄，反覆出錯的地方寫在本頁，作為修改規則的依據。

## 4. 還可以再改進的地方（尚未實作）

- **字數檢查寫進 lint**：這次是用臨時腳本算字數，可以併入 `tools/lint.py`，改成 warning。
- **內容比對半自動化**：把逐頁稿每一句跟筆記比對，找不到相近句子的列出來給人看（只能輔助，不能取代人工）。
- **自動截圖**：把「逐頁截圖＋拼成總覽圖」寫成工具，讓節點 7 的檢查每次都做、而且做法一致。

以上三項要改 `tools/`，需要使用者同意。
